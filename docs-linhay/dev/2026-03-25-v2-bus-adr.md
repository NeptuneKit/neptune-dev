# ADR: `/v2` 双向总线命名与上行入口收敛（2026-03-25）

## 状态
Accepted

## 决策
1. `/v2` 继续执行 **`/v2 only`**，不新增历史别名兼容层。  
2. 总线相关字段命名以“实现统一线”为准：`requestId / direction / kind / command / payload / timestamp`。  
3. ACK 统一语义：`status in {ok,error}`，以 `status=ok` 表示 accepted。  
4. 客户端上行入口锁定为 **`POST /v2/logs:ingest`**（短期唯一稳定入口）。  
5. `direction` 仅允许：`cli_to_client`、`client_to_cli`。  
6. 日志存储责任在客户端，网关仅做转发/聚合/中继；`/v2/logs` 在网关可用时始终返回 `200`（失败明细走 `meta.partialFailures`）。  

## 为什么这样定
- 当前 Gateway + iOS + Android + Harmony 已按 `requestId/command/status` 形成可运行闭环。
- 如果此时再切回另一套命名，会增加多端二次迁移成本并拉长联调周期。
- 上行入口收敛到 `logs:ingest` 可以避免“总线入口 vs ingest 入口”并存造成接入歧义。

## 影响范围
- `neptune-contracts`：下一版 OpenAPI 与 schema 字段命名对齐到 `requestId/kind/command/status`。
- `neptune-gateway-swift`：保持现有行为，补充注释与错误码文档。
- `neptune-sdk-ios/android/harmony`：保持现有实现字段，不再引入平行命名。

## 不变量（联调基线）
- 单目标回调超时：`3s`。  
- 聚合摘要延迟：沿用网关默认 `10s`。  
- 注册 TTL：`120s`，续约刷新在线状态。  
- `usbmuxd` 仅在 macOS Gateway/CLI 侧启用，失败回退 `httpCallback`。  

## 验收标准
1. CLI `command.send(ping)` 下发后，能够收到 `event.command_ack` 与 `event.command_summary`。  
2. 三端客户端均可通过 `POST /v2/client/command` 返回 `status=ok/error` ACK。  
3. `GET /v2/logs` 支持“指定客户端过滤路由”与“无过滤 fan-out 聚合”；上游失败不阻断网关 `200` 响应。  
4. `GET /v2/metrics` 不再暴露 `totalRecords/droppedOverflow`。  
5. 注册校验失败路径一致：`callbackEndpoint` 必填且合法；`usbmuxdHTTP` 时 `usbmuxdHint` 条件必填。  

## 后续动作（一次性收敛）
1. contracts 发布 `v2.0.0-alpha.2`：更新 BusEnvelope/BusAck 命名到本 ADR。  
2. 各 SDK 与 Gateway 增加契约一致性测试（字段级 encode/decode + 必填校验）。  
3. 更新对外文档，明确“上行唯一入口 = /v2/logs:ingest”。
